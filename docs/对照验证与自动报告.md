# HF / FlashInfer / vLLM 对照验证与自动报告

新增工具分为两个独立环节：先验证输出，再测性能。全部模型执行在服务器进行；本地可以对下载的日志重新生成汇总，不依赖 torch。

## 1. 真实模型正确性检查

环境安装完成后，从仓库根目录运行：

```bash
python -m scripts.check_inference_correctness \
  --model /root/bayes-pub/models/DeepSeek-R1-Distill-Qwen-1.5B \
  --gpu 0 --output-tokens 32
```

默认串行启动 HF、FlashInfer eager、FlashInfer Graph、vLLM 四个独立进程，避免四个引擎同时占用显存。限制单 GPU、BF16、基础模型、greedy、忽略 EOS，不涉及 LoRA 的非零参数正确性。

测试输入在父进程统一编码，保存为 `cases.json`，所有后端使用完全相同的 token IDs。长度为 31、32、33、129，覆盖默认 32-token 页边界及长于一页的请求。为精确控制 token 长度，会重复/截取编码结果；它是执行正确性输入，不是自然语言质量评测数据集。

检查内容：

- HF vs FlashInfer/vLLM 的 greedy token 序列；记录第一个分叉位置及不同 token。
- HF vs FlashInfer 的冷请求首步完整 logits，记录最大绝对误差、RMSE、argmax、参考 top1/top2 间距和 allclose。
- FlashInfer 同一请求冷缓存/复用缓存的序列一致性，并要求复用命中数大于零。
- Graph vs eager 的直接序列对比；Graph worker 要求实际成功 replay 数大于零，不能只检查参数开关。
- 固定输出长度，任一进程失败或上述严格检查失败，主命令返回非零。

默认 logits 筛查容差是 `atol=0.1, rtol=0.01`，可用命令参数调整。它们是 BF16 初筛设置，不是所有模型都应满足的理论误差界。严格失败不直接等于实现 bug：先看首处分叉与 logits 间距，再定位原因；不要仅为了变绿任意放宽容差。

完整 logits 仅比较第一步 prefill。后续 decode 对比 token 序列，不做逐步 teacher-forcing logits 对照。vLLM 使用公开 generate API，仅比较序列，不提取内部完整 logits。当前不覆盖并发、多适配器、OOM 回收或所有模型结构。

默认四项都要跑。若 vLLM 尚未装好，可以先明确选择子集：

```bash
python -m scripts.check_inference_correctness \
  --model /root/bayes-pub/models/DeepSeek-R1-Distill-Qwen-1.5B \
  --variants hf flashinfer_eager flashinfer_graph --gpu 0
```

子集通过只能报告该子集，不能解释为 vLLM 对照也通过。HF 参考不可省略。

输出位于 `course_results/correctness_<UTC时间>/`：

| 文件 | 内容 |
|---|---|
| `cases.json` | 实际输入 token IDs |
| 各后端 `.json` | 输出 IDs、可用 logits、版本与设备信息、复用/重放信息 |
| 各后端 `.log` | 加载、执行、捕获与报错原文 |
| `runs.json` | 命令及退出状态 |
| `report.json` / `report.md` | 严格检查结果、误差和范围限制 |

正确性工具包含 CPU logits 拷贝和插入的采集逻辑，**不将这里的耗时作为性能结果**。

## 2. 性能与显存采样

原启动命令保持可用，现已自动附加采样和报告：

```bash
python -m scripts.run_course_experiments \
  --model /root/bayes-pub/models/DeepSeek-R1-Distill-Qwen-7B \
  --gpu 0 --suite core --prompt-lengths 512 2048 \
  --output-tokens 128 --warmup-runs 2 --measure-runs 5
```

每项任务开始前启动独立线程调用 `nvidia-smi`，默认每 0.5 秒采样一次，任务结束后保存 `<任务名>.memory.json`。可通过 `--memory-interval 1` 调整间隔。采样命令超时或不可用时记录 errors，缺失峰值为 null，不伪造为零。

**统计范围为整张物理 GPU，包含模型加载、预热和测量。** 记录 baseline、采样次数、时间戳、设备已用/总显存和利用率。它包含其它进程、引擎预分配，并可能遗漏瞬时峰值；不能称为单请求或某进程精确峰值，不能直接据此声称某引擎 KV 占用更低。

采样在测量进程外，不往 token 循环插入同步；但仍有外部查询开销。固定采样间隔、保证独享卡，性能差异很小时考虑复跑确认。

## 3. 自动汇总

每完成一个任务（包括失败任务），更新以下文件：

- `summary.md`：用于阅读的结果表。
- `summary.json`：完整汇总字段与有效性标记。
- `summary.csv`：可用 Excel 或绘图工具打开。
- `measurements.csv`：逐次测量结果，排除 warmup。

汇总从原始日志的 `measure#` 行读取实际输入/输出长度和耗时。基础实验输出 mean、p50、p95、总输出 tokens 除总测量时间的吞吐；前缀实验额外输出首请求与后续复用请求的平均延迟。采样显存以明确命名的 `device_sampled_peak_mib` 单独列出。

`total_tokens_per_s` 是比值的整体口径，不是逐请求 tok/s 的简单平均，因此可能与原日志里的 `mean_tokens_per_s` 略有差异。p95 使用线性插值，小样本不应过度解读。日志当前保留四位小数，汇总继承这个精度。

状态说明：

- `ok`：任务退出成功，测量次数完整，实际输出长度达到设置值。
- `incomplete`：退出成功，但测量不足或输出被提前截断。
- `failed`：退出非零、缺少测量或日志无法解析；查看 returncode/error 和原始日志。

Graph 端到端加速比只对配对的 FlashInfer off/on 计算，要求命令除了 Graph 开关外一致、实际 prompt 范围和输出样本相同、两项均为 ok。不是 HF 或 vLLM 全面性能排名。

## 4. 下载到本地后重新汇总

保留 `runs.json`、各任务 `.log` 与 `.memory.json` 的同级目录结构：

```bash
python -m scripts.summarize_experiments /path/to/core_2026...
```

报告器优先根据日志文件名查找本地同级文件，不依赖服务器绝对路径。CSV 使用 UTF-8 BOM，便于 Windows Excel 打开。当前不自动渲染图片，避免绘图库依赖阻挡实验；后续可直接从 CSV 画结果图。

## 5. 本地验证与服务器反馈

不装 torch 也能运行：

```bash
python -m unittest test.test_benchmark_artifacts test.test_course_experiments -v
```

这些测试验证分叉定位、误差统计、warmup 排除、前缀解析、固定输出识别、加速比配对、采样失败处理和实验矩阵，不冒充 CUDA 模型验证。本轮尚未实际运行服务器 GPU 路径。
