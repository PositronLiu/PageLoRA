# 从代码到最终实验：操作清单

## 换卡：T4 预实验 / H800 完整实验

新增 `--dtype auto|float16|bfloat16`：实际运行时探测选中 GPU，T4 自动 FP16，支持 BF16 的 4090/H800 自动 BF16。所有后端统一精度，硬件、显存容量、计算能力、torch/CUDA 和最终精度写入结果。强制不支持的 BF16 会提前报错。`--dry-run` 不探测设备，auto 会保留到实际运行时解析。

**T4 / 16GB 先用共享的 1.5B 模型：**

```bash
python -m scripts.run_final_experiments \
  --profile t4 --dtype auto \
  --model /root/bayes-pub/models/DeepSeek-R1-Distill-Qwen-1.5B \
  --prompt-lengths 512 --output-tokens 32 \
  --warmup-runs 1 --measure-runs 3 --max-model-len 2048 \
  --output-dir /root/bayes-tmp/pagelora-t4
```

T4 档只跑 HF/vLLM 正确性与核心性能，主动省略 FlashInfer、Graph 消融和 prefix 阶段。当前依赖版本在 T4 上尚未验证，FP16 适配不保证 vLLM wheel 或内核支持 SM75；若安装、导入或运行提示不支持架构，请把报错发回来，不要混装旧依赖。此时也可先单独跑 HF 留下可用基线：

```bash
python -m scripts.run_course_experiments \
  --model /root/bayes-pub/models/DeepSeek-R1-Distill-Qwen-1.5B \
  --dtype float16 --backends hf --suite core \
  --prompt-lengths 512 --output-tokens 32 --max-model-len 2048 \
  --warmup-runs 1 --measure-runs 3 \
  --output-dir /root/bayes-tmp/pagelora-t4-hf
```

T4 预实验成功时入口返回 0，但报告仍标注结题证据不完整，这是预期行为；`--report-only` 按完整实验标准检查会返回非零。不要用这个预实验替代 PageLoRA 优化验证。

**后续 H800 / 80GB：**重新确认镜像与依赖，然后执行完整矩阵：

```bash
python -m scripts.run_final_experiments \
  --profile full --dtype auto \
  --model /root/bayes-pub/models/DeepSeek-R1-Distill-Qwen-7B \
```

若要研究跨卡差异，H800 上额外用相同 1.5B 模型、长度和 FP16 跑一份 `--profile t4 --dtype float16`。跨卡差异与模型大小、精度变化必须区分；PageLoRA 相对基线的加速应来自同卡同配置对照。换实例前先下载整个结果目录，旧实例缓存不保证挂到新实例上。

在平台终端执行，项目和缓存放到可写缓存盘：


## 5. 失败时看什么、怎么重跑

每次运行新建 `final_时间戳`，内部有 `correctness_*`、`core_*`、`prefix_*`。错误位置：

- 环境与版本：各阶段 `metadata.json`。
- 正确性：`correctness_*/report.md`、`report.json` 及各后端 `.log`。
- 性能：`core_*` 或 `prefix_*` 下对应任务 `.log`、`summary.md`。
- 总体进度与失败原因：`pipeline.json`，中断时也尽量保存。

修复后重新执行命令生成新目录，不覆盖旧证据。当前总入口不做跨目录自动续跑，以免误用旧源码结果。若只是整理已下载结果：

```bash
python -m scripts.summarize_experiments /实际路径/core_时间戳
python -m scripts.summarize_experiments /实际路径/prefix_时间戳
python -m scripts.run_final_experiments --report-only /实际路径/final_时间戳
```
