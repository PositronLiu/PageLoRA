# 从代码到最终实验：操作清单

## 1. 本地准备仓库

先检查变更，再由你提交并推到新仓库；不要上传 `cloud_server_pics`、密码、模型权重或实验缓存。本文命令中的 `<你的仓库地址>` 需要替换。

代码现在提供：正确性门禁、HF/vLLM/FlashInfer 对照、CUDA Graph 开关消融、前缀缓存 reset 对照、显存采样、CSV/Markdown 自动汇总和源码快照。尚未有这台服务器的实测结果，不能先填写加速比。

## 2. 服务器拉取与环境

在平台终端执行，项目和缓存放到可写缓存盘：

```bash
cd /root/bayes-tmp
git clone <你的仓库地址> PageLoRA-final
cd PageLoRA-final
python -m venv /root/bayes-tmp/pagelora-env
source /root/bayes-tmp/pagelora-env/bin/activate
export HF_HOME=/root/bayes-tmp/hf-cache
export XDG_CACHE_HOME=/root/bayes-tmp/cache
export TMPDIR=/root/bayes-tmp/tmp
mkdir -p "$HF_HOME" "$XDG_CACHE_HOME" "$TMPDIR"
python -m pip install --upgrade pip
python -m pip install -r requirements.txt ninja
python -m pip check
```

**安装是第一个检查点。** requirements 固定版本是项目目标环境，不是已在你的镜像验证过的组合；你原有 torch 2.4.1 不等同于目标依赖。新建独立环境会下载另一套 torch/vLLM，注意缓存盘容量。若解析冲突、下载失败或 FlashInfer 编译失败，保留完整报错发回来，不要自行混装多版 torch。驱动显示 CUDA 13.0 不代表必须安装 CUDA 13 工具链；当前系统 nvcc 为 12.4，JIT 是否兼容要实测。

```bash
nvidia-smi
df -h /root/bayes-tmp
python -c "import torch,transformers,flashinfer,vllm; print('torch',torch.__version__,'runtime',torch.version.cuda); print(torch.cuda.get_device_name(0)); print('BF16',torch.cuda.is_bf16_supported())"
python -m unittest test.test_benchmark_artifacts test.test_course_experiments test.test_final_experiments -v
```

## 3. 先用 1.5B 跑通，不直接烧正式实验时间

```bash
python -m scripts.run_final_experiments \
  --model /root/bayes-pub/models/DeepSeek-R1-Distill-Qwen-1.5B \
  --prompt-lengths 512 --output-tokens 32 \
  --warmup-runs 1 --measure-runs 2 \
  --output-dir /root/bayes-tmp/pagelora-smoke
```

总入口顺序为：四后端正确性 → core 性能 → prefix 性能。任一阶段失败就停止，不把缺失样本当成功。首次 FlashInfer JIT 或 graph capture 较慢，进程仍在运行时先看对应日志。正确性比较 BF16 logits 与完整贪心 token 序列；不一致需结合首个分歧和浮点误差分析，不能简单调大容差当通过。

## 4. 正式 7B 实验

建议在平台持久终端或 tmux 中运行（若装有 tmux，可先执行 `tmux new -s pagelora`），避免浏览器关闭中断进程。确保无其他 GPU 任务。

```bash
python -m scripts.run_final_experiments \
  --model /root/bayes-pub/models/DeepSeek-R1-Distill-Qwen-7B \
  --prompt-lengths 512 2048 --output-tokens 128 \
  --warmup-runs 2 --measure-runs 10 --max-model-len 8192 \
  --output-dir /root/bayes-tmp/pagelora-results
```

4090 D/24GB 可作为这套 7B BF16 单卡实验的目标设备，但实际峰值取决于框架预分配和 KV 容量，以实测为准。OOM 时先保存日志；可先用 512 长度诊断，不把不同配置的结果混在同一结论里。运行中不要修改代码，入口会检查源码是否变化。无需训练 LoRA 或下载数据集；此矩阵测 base 模型推理，不能据此宣称多 LoRA 服务加速。

## 5. 失败时看什么、怎么重跑

每次运行新建 `final_时间戳`，内部有 `correctness_*`、`core_*`、`prefix_*`。错误位置：

- 环境与版本：各阶段 `metadata.json`。
- 正确性：`correctness_*/report.md`、`report.json` 及各后端 `.log`。
- 性能：`core_*` 或 `prefix_*` 下对应任务 `.log`、`summary.md`。
- 总体进度与失败原因：`pipeline.json`，中断时也尽量保存。

修复后重新执行命令生成新目录，不覆盖旧证据。当前总入口不做跨目录自动续跑，以免误用旧源码结果。若只是整理已下载结果：

```bash
python -m scripts.summarize_experiments /实际路径/core_时间戳
python -m scripts.summarize_experiments /实际路径/prefix_时间戳
python -m scripts.run_final_experiments --report-only /实际路径/final_时间戳
```

## 6. 跑完给我哪些文件

下载整个 `final_时间戳` 文件夹，不只截屏。包括源码 `source.zip`/哈希、正确性证据、环境版本、原始日志、显存采样、逐请求 CSV、汇总和 `final_report.md`。缓存盘停止任务四天后可能清理，及时备份到本地。

`final_report.md` 自动填写实测表格及证据状态，结果解释仍需根据数据完成。拿到结果后即可据此整理性能图、加速或退化原因、实验局限，并替换进度 PPT 中的待测部分；当前不预填不存在的数值。最终材料应包含：问题与方法、实现、正确性、对照与消融、真实结果和局限。
